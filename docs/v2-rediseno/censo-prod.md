## ✅ Conclusiones del censo para la spec

1. **La lógica vive en ~150 funciones SQL + ~120 triggers con orden alfabético forzado** (`trg_00_`, `trg_z_`, `trg_zzz_`) — insostenible, y la razón de fondo del rediseño.
2. Hay **capas enteras ya diseñadas sin operar** (SII nativo, referencias OC, conciliación, agentes, RAG, splits): la spec v2 decide cuáles son modelo base y cuáles se descartan.
3. El volumen de datos NO es problema para el cutover; la fidelidad semántica sí → casos dorados + mirroring.
4. Duplicaciones evidentes a matar en v2: 3 triggers de updated_at en una tabla, familias `_safe/_robust/_direct`, 2 generadores de facturas conviviendo en `contracts`.
